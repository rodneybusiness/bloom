# A Pattern Language: How Places Come Alive · Course Syllabus

> This syllabus defines everything you will be able to do after completing this course.
> Learning depth: Standard
> The number of lessons varies by learner, but the mastery items do not get watered down.

## Core Mastery Items

After completing this course, you will be able to:

### 1. The Anatomy of a Pattern
- [x] Able to define a pattern as a recurring **context – forces – solution** triad, and identify all three parts in any written pattern
- [x] Able to read one of Alexander's actual patterns (e.g., #159 *Light on Two Sides of Every Room*) and restate, in your own words, the conflicting forces it resolves
- [x] Able to explain the asterisk confidence ratings, and why every pattern is a falsifiable hypothesis rather than a rule

### 2. From Patterns to a Language
- [x] Able to explain what makes 253 patterns a *language* rather than a checklist: the network of upward/downward links and the ordering from large scale to small
- [x] Able to select and sequence a handful of patterns into a coherent mini-language for a concrete design problem (e.g., a home office, a neighborhood café)
- [x] Able to explain generative unfolding: why applying patterns in order "grows" a design the way grammar generates sentences, and how this differs from assembling parts
- [x] Able to explain piecemeal growth and why Alexander opposed master planning

### 3. The Deeper Theory: Life, Wholeness, and Evidence
- [x] Able to articulate the "quality without a name" (QWAN) and Alexander's claim that aliveness in places is objective, not mere taste
- [x] Able to explain the relationship between *A Pattern Language* and *The Timeless Way of Building* (the language itself vs. the theory behind it)
- [ ] Able to critique a pattern: describe what evidence would show that a given pattern is wrong, or bound to a culture/context

### 4. Legacy and Practice: Pattern Languages Beyond Architecture
- [ ] Able to trace how pattern languages jumped to software — design patterns and the wiki — and state what was preserved and what was lost in translation
- [ ] Able to write a small original pattern in Alexandrian form (name, context, forces, solution, links) for a domain of your choice, and judge whether a domain is suited to pattern-language treatment at all

## Not Covered in This Course

- Memorizing all 253 patterns individually (we work closely with a representative dozen)
- The mathematics of *The Nature of Order* (the 15 properties appear only at the intuition level)
- Professional architectural practice: building codes, structural engineering, drafting
- A catalog tour of software design patterns (GoF appears only as legacy, not curriculum)
- Urban-planning policy debates (New Urbanism, zoning reform) beyond their direct link to Alexander
